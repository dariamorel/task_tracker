# Task Tracker

## Доменная область

Трекер задач с тегами и приоритетами. На главном экране
отображается список задач. Пользователь может:

- создавать задачи с названием, приоритетом и необязательным тегом;
- отмечать задачи выполненными;
- редактировать задачу (название, приоритет, тег);
- удалять задачи;
- создавать, переименовывать и удалять теги прямо при выборе тега у задачи.

Реализован полный CRUD над двумя связанными сущностями: `Tag` и `Task`.

## Стек реализации

| Слой | Технология |
|---|---|
| Backend | Kotlin, Spring Boot, REST / HTTP/1.1 |
| СУБД | PostgreSQL 16 |
| Доступ к данным | Spring `JdbcClient` + HikariCP |
| Миграции | Flyway |
| Frontend | `index.html` + `styles.css` + `app.js` |
| Сборка | Gradle Wrapper |
| Логирование | SLF4J + Logback |
| Окружение | Docker, Docker Compose |

UI: `src/main/resources/static/` (`index.html`, `styles.css`, `app.js`).

Схема БД: `src/main/resources/db/migration/V1__init.sql`.

## Основные сущности

**Tag** - тег задачи.

| Поле | Тип |
|---|---|
| `id` | BIGSERIAL, PK |
| `name` | TEXT, NOT NULL, UNIQUE |

**Task** - задача. Тег необязателен, при удалении тега у связанных задач
`tag_id` становится `NULL` (`ON DELETE SET NULL`).

| Поле | Тип |
|---|---|
| `id` | BIGSERIAL, PK |
| `title` | TEXT, NOT NULL |
| `done` | BOOLEAN, NOT NULL, DEFAULT FALSE |
| `priority` | TEXT, NOT NULL, DEFAULT `MEDIUM`, доступны `LOW`, `MEDIUM`, `HIGH` |
| `tag_id` | BIGINT, NULL, FK - `tags.id` |

Список задач на API упорядочивается по приоритету (HIGH → MEDIUM → LOW), затем по `id`.

REST API:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/tags` | список тегов |
| GET | `/api/v1/tags/{id}` | тег по id |
| POST | `/api/v1/tags` | создать тег |
| PUT | `/api/v1/tags/{id}` | переименовать тег |
| DELETE | `/api/v1/tags/{id}` | удалить тег |
| GET | `/api/v1/tasks?tagId=` | список задач (фильтр по тегу необязателен) |
| GET | `/api/v1/tasks/{id}` | задача по id |
| POST | `/api/v1/tasks` | создать задачу |
| PUT | `/api/v1/tasks/{id}` | обновить задачу |
| DELETE | `/api/v1/tasks/{id}` | удалить задачу |
| GET | `/health` | проверка работоспособности |

Тела запросов и ответов — JSON. Ошибки:
`404` — объект не найден; `400` — ошибка валидации.

## Пользовательский интерфейс

UI — одностраничный, тёмная тема. На главном экране:

1. форма создания задачи (название, приоритет, выбор тега);
2. список задач в виде карточек.

На карточке задачи отображаются чекбокс выполнения, название, цветная метка
приоритета и тег (если задан). Справа - иконки редактирования и корзины. Задачи отсортированы по приоритету.
Теги управляются рядом с выпадающим списком тегов (в форме создания и в
диалоге редактирования задачи). При удалении тега он снимается со всех задач. При изменении тэга он обновляется у всех, связанных с ним задач.

## Запуск

Задать POSTGRES_PASSWORD:
```bash
cp .env.example .env 
```

Запустить приложение:
```bash
docker compose up --build
```

UI: http://0.0.0.0:8080/

## Соответствие 12 факторам

### 1. Кодовая база
Один git-репозиторий содержит бэкенд, фронтенд, миграции и описание окружения.
Из него разворачиваются все окружения. 

### 2. Зависимости
Все зависимости явно объявлены в `build.gradle.kts`, версии зафиксированы 
через BOM `spring-boot-dependencies:4.1.1`, JDK — через `jvmToolchain(21)`. 
Сборка и запуск изолированы в Docker-образах.

### 3. Конфигурация
Вся конфигурация берётся из переменных окружения: `PORT`, `DATABASE_URL`,
`DATABASE_USER`, `DATABASE_PASSWORD`. Файл `application.yml` не содержит
значений, зависящих от окружения, он только связывает переменные со свойствами
Spring (`url: ${DATABASE_URL}`). В коде нет адресов, логинов и паролей. Пароль локально
хранится в `.env` (в `.gitignore`), в репозитории только `.env.example` как пример.

### 4. Сторонние сервисы
PostgreSQL задается строкой `DATABASE_URL`. Код
одинаков для локальной БД в контейнере и облачной БД: замена сервиса происходит за счет 
смены переменной окружения, без изменения кода.

### 5. Сборка, релиз, запуск
- **Build** — `docker compose build` (внутри `./gradlew installDist`) даёт
  неизменяемый образ `task-tracker:<APP_VERSION>`
- **Release** — образ + переменные окружения
- **Run** — запуск контейнера из готового образа без компиляции в рантайме

### 6. Процессы
Процесс stateless: нет сессий и кэшей данных в памяти, на диск приложение
ничего не пишет. Состояние - в PostgreSQL. Процесс можно перезапустить или
перенести на другую машину без потери данных.

### 7. Привязка портов
Приложение - HTTP-сервер: Tomcat встроен как библиотека и
запускается из `main`, а не приложение деплоится во внешний Tomcat/Apache.
Порт - из `PORT` (по умолчанию 8080). Фронтенд отдаётся тем же процессом,
весь сервис доступен через один порт.

### 8. Параллелизм
Масштабирование горизонтальное - дополнительные одинаковые процессы
(`docker compose up --scale app=N` за балансировщиком). Главного процесса нет.
Типы процессов разделены: web (`AppKt`) и admin (`MigrateKt`) из одного образа.

### 9. Утилизируемость
Старт ~2 с, без тяжёлой инициализации, схема БД при старте web-процесса не
создаётся. По SIGTERM - graceful shutdown (`server.shutdown: graceful`):
Tomcat перестаёт принимать новые запросы, дожидается текущих (до 10 с), затем
закрывается пул HikariCP. Процесс в контейнере - PID 1, сигнал
доходит до JVM. Внезапное падение безопасно: данные в БД, незавершенные
транзакции откатывает СУБД.

### 10. Паритет разработки и продакшена
Везде одинаковы: PostgreSQL 16, образ приложения, способ
конфигурации и Flyway-миграции. Локально окружение поднимается командой
`docker compose up --build`.

### 11. Логирование
Logback (Spring Boot по умолчанию) пишет только в stdout.

### 12. Административные задачи
Миграции — одноразовый процесс `MigrateKt` (`./gradlew migrate` или сервис
`migrate` в docker-compose до старта `app`). Тот же образ, те же переменные
окружения и зависимости, что у web-процесса. Автозапуск Flyway при старте
Spring не используется. Схема описана в `V1__init.sql` в git, ручных изменений
на сервере нет.
